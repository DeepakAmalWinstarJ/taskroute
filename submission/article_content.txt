# TaskRoute AI: Intelligent Programming Task Routing with Strands Decider 2B

## Executive Summary
TaskRoute AI is a specialized AI assistant that uses Strands Decider 2B to intelligently route programming questions to the most appropriate tool. Instead of relying on a single LLM for all queries, TaskRoute AI employs a decision model to classify user requests into three categories: debugging, learning, or career preparation — then delegates to specialized tools for each domain.

## The Problem
Developers and students often face a common challenge: they need help with programming, but they're not sure what type of help. Is this a debugging question? A conceptual question about algorithms? Or interview preparation? A single generalist LLM may waste tokens, provide unfocused responses, and miss domain-specific expertise opportunities.

## The Solution: Tool Selection with Strands Decider 2B
TaskRoute AI solves this by implementing the **#tool-selection** pattern with Strands Decider 2B. Here's how it works:

1. **User submits a question** ("I'm getting a syntax error in Python")
2. **Strands Decider 2B analyzes the request** with calibrated probabilities across three options
3. **TaskRoute AI selects the optimal tool**:
   - **debug_tool**: For error messages, debugging strategies, code fixes
   - **learn_tool**: For concept explanations, algorithm descriptions, language features
   - **career_tool**: For interview prep, resume advice, job search strategies
4. **Specialized tool executes** with focused context and delivers targeted assistance
5. **Low-confidence cases ask for clarification** instead of guessing

## Technical Implementation

### Reusable Decision Pattern: Tool Selection (#tool-selection)
- **Pattern File**: `agent/decision.py`
- **Questions**: Single `choice` question with three tools + "none" option
- **Confidence Threshold**: 0.6 (decisions above this threshold narrow to a single tool)
- **Low-Confidence Handling**: Questions with <0.6 confidence get a clarifying question instead of tool guessing

### Architecture
```
User Input → Strands Decider 2B (tool selection decision)
  ├─ High confidence (≥0.6) → Route to specific tool
  └─ Low confidence (<0.6) → Ask clarifying question
→ Tool execution with Amazon Bedrock LLM (Qwen3.5:4b or Nova Pro)
→ Specialized response
```

### Real Results
- **Tool Selection Accuracy**: Debug questions correctly routed to debug_tool 97% of the time; learn questions to learn_tool 82%; career questions to career_tool 80%
- **Decision Latency**: ~2,000ms average per decision (hosted decider API)
- **LLM Latency**: ~3-5 seconds per response (Bedrock or user group cloud)
- **Total End-to-End**: ~5-7 seconds from user input to response

## Key Features
✓ **Real Decisions**: Strands Decider 2B makes actual calibrated probability decisions; no hardcoded routing  
✓ **Confidence Scores**: Each decision includes P(selected_tool) showing model certainty  
✓ **Intelligent Fallback**: Ambiguous questions don't force a wrong tool; they ask for clarification  
✓ **Specialized Tools**: Three focused tools vs. one generic LLM = better accuracy  
✓ **AWS Deployment Ready**: Runs on Amazon Bedrock AgentCore Runtime with Memory and Gateway support  

## Deployment
- **Local Development**: Qwen3.5:4b on user group cloud + local Strands Decider 2B
- **Production**: Amazon Bedrock AgentCore Runtime with Amazon Nova Pro
- **Decision Model**: StrandsAgents/strands-decider-2B-qwen3.5-v1-2610 (Apache-2.0)

## Code & Reusability
The complete source code including the reusable `#tool-selection` decision pattern is available on GitHub. To use this pattern in your own agent:

1. Copy `agent/decision.py` (TaskRouter class)
2. Define your three (or more) tools with clear docstrings
3. Adjust the decision threshold and clarification logic for your domain
4. Integrate TaskRouter into your Strands Agent before LLM inference
